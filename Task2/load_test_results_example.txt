ОЖИДАЕМОЕ ПОВЕДЕНИЕ:
--------------------
1. При увеличении нагрузки утилизация памяти должна расти
2. Когда утилизация превысит 80%, HPA начнет создавать новые реплики
3. Количество реплик может увеличиться до 10 (максимум)
4. После снижения нагрузки реплики постепенно уменьшаются

ПРОВЕРКА РЕЗУЛЬТАТОВ:
---------------------
Для проверки результатов выполните:

1. Проверить текущее состояние HPA:
   kubectl get hpa scaletestapp

2. Посмотреть детальную информацию:
   kubectl describe hpa scaletestapp

3. Проверить количество реплик:
   kubectl get deployment scaletestapp

4. Посмотреть метрики подов:
   kubectl top pods -l app=scaletestapp

5. Посмотреть события масштабирования:
   kubectl get events --sort-by='.lastTimestamp' | grep scaletestapp

ПРИМЕР КОМАНД ДЛЯ МОНИТОРИНГА:
-------------------------------
# Непрерывный мониторинг реплик
watch -n 2 'kubectl get hpa scaletestapp && echo "" && kubectl get pods -l app=scaletestapp'

# Или используйте скрипт
./Task2/monitor_replicas.sh

ПРИМЕЧАНИЯ:
-----------
- HPA проверяет метрики каждые 15 секунд
- Масштабирование вверх происходит быстро (окно стабилизации 0 сек)
- Масштабирование вниз происходит медленнее (окно стабилизации 300 сек)
- Для генерации достаточной нагрузки может потребоваться увеличить количество пользователей
